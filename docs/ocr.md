# 本地图片选字

点击橡皮擦右侧的「方框＋文」，识别后直接在图片上拖选。框选按字符坐标命中，因此可以选择表格某一列的多行内容；同一行的不同识别块复制时以制表符分隔，跨行以换行分隔。单击选择英文词或单个中文字符，双击选择识别行。Ctrl+A 全选，Ctrl+C 复制选中文字；工具栏另有复制全部和返回标注。

图片缩放时选区同步缩放，高亮不进入图片导出。图片在识别期间被修改或调整边界时，旧结果不会覆盖新图片；关闭截图后不再显示迟到的识别结果。

## GitHub 项目选择

| 项目 | 对本项目的适用性 |
| --- | --- |
| [BobLd/RapidOcrNet](https://github.com/BobLd/RapidOcrNet) | 已应用。Apache-2.0，ONNX Runtime + SkiaSharp，提供字符坐标；无需 OpenCV，适合直接在图片上选字。4.2.0 需要 .NET 8，因此使用独立、常驻的本地识别进程，保持截图主程序的 .NET Framework 4.8。 |
| [RapidAI/RapidOCR](https://github.com/RapidAI/RapidOCR) | RapidOcrNet 的上游路线；模型和推理方案成熟，但直接引入 Python 部署会增加当前 Windows 程序的依赖。 |
| [raoyutian/PaddleOCRSharp](https://github.com/raoyutian/PaddleOCRSharp) | 支持 .NET Framework，适合直接集成；本次选择提供逐字坐标且依赖更少的 RapidOcrNet 路线。未做同机横向性能比较。 |

NuGet 版本由 `ocr-host/packages.lock.json` 固定；模型文件来源、字节数和 SHA256 固定在 `ocr-host/models.lock.json`，构建时校验。模型不进入 Git，也不会在用户识别截图时联网下载。许可证随便携组件提供。

## 已应用的提速措施

- 默认 PP-OCRv6 **small 多语言模型**，输出限定为中英文、数字和标点；检测短边目标 480，相比 736 设置减少检测计算量，保留较好的数字和标点识别。
- 普通截图不做方向分类推理；不适合竖排、倒置或大角度旋转文字。
- 鼠标停留在识别按钮时预加载；截图间复用模型与 ONNX 会话，限制线程数，避免每次启动解释器或重新载入模型。
- 同一张图片重复识别直接复用上一份结果。图像只在本地进程间传递，不上传服务器。
- 输出限于中英文、数字、常用标点与货币符号。输出字符过滤用于限定内容，**并不意味着裁剪字典后会等比例提速**。

## 本地实测

2026-10-22，在当前 Linux x64 工作环境、CPU ONNX Runtime 下测试两张 1120×240 合成截图：24px 中英混排、16px 表格式文本。各配置先加载模型，每张图片识别 3 次；表中为后两次引擎耗时范围，不包含 UI、PNG 编码和剪贴板耗时，也没有使用主程序的结果缓存。

| 模型 / 检测限制 | 24px 混排，预热后 | 16px 表格文本，预热后 | 样图观察 |
| --- | --- | --- | --- |
| tiny / 480 | 306–310 ms | 296–308 ms | `ShotInk` 被读成 `Shotlnk`，部分标点和货币符号有误差 |
| tiny / 736 | 621–667 ms | 652–653 ms | 仍有相似字符误差 |
| **small / 480，默认** | **580–595 ms** | **545–565 ms** | 样图中英文、数字和标点正确；部分相邻表格单元格合成同一识别行 |
| small / 736 | 1224–1242 ms | 1208–1218 ms | 表格单元格分离较完整，耗时更高 |

以上只比较同一引擎的配置，不能推出比微信、Windows OCR 或其他项目快多少。真实耗时随 CPU、图片尺寸、文字密度变化；Windows 下还需实机验证。字符坐标支持在合并的识别行中选取局部内容，但复杂表格的阅读顺序不保证完全恢复。

样图和可复现实测脚本见 `tests/fixtures/ocr-*` 与 `tests/ocr-benchmark.py`。开发调试可给识别进程传入 `--fast` 使用 tiny 模型，或 `--quality` 使用 736 检测限制；截图主程序采用上述默认设置。

## 构建和部署

Windows 安装 .NET SDK 8 或更新版本后，运行 `build.ps1 -Test`；脚本下载并校验模型，将 OCR 组件发布为自带运行时的 win-x64 程序，随 `ShotInk-portable.zip` 提供。用户需完整解压并保留 `ocr` 文件夹，系统还需安装 Microsoft Visual C++ 2015–2022 x64 运行库（ONNX Runtime 的原生依赖）。截图主程序仍为 .NET Framework 4.8，OCR 子进程为 .NET 8；独立 EXE 缺少配套文件时会提示使用便携包。

识别可能混淆 I/l/1、O/0 或相似标点；复制后请核对关键编号、金额。当前没有针对专业票据、手写字、竖排文字做专项优化。
